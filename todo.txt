Todo list.  Open items only - finished work is written up in the commit
messages that made the changes, not kept here.

- the web keyboard work needs one pass by hand in a real browser.  nothing in
this repo can prove it: there is no node and no emcc on the build box, so the
wasm was never rebuilt and the page was only syntax-checked.  open it, click
the terminal, press Ctrl+R and confirm the page does not reload and the CCP
retypes the line.  then Ctrl+Shift+R, which is the one the handler had to add.
then check the exclusions still work: Ctrl+Shift+V must paste, Ctrl+Insert must
copy a selection, Ctrl+Minus must zoom.  then move focus to the ROM select and
press ArrowDown twice - it must reach the second entry, not send ESC [ B to
CP/M.  then write to a disk and close the tab to see the beforeunload guard.

- the IEXTEN clear cannot be proven on linux.  it is there because BSD/XNU
gates VLNEXT (^V) and VDISCARD (^O) on IEXTEN alone, outside the ICANON block;
on linux those sit inside it and are already off once ICANON is, so a linux run
passes with or without the clear.  someone with a mac should start WordStar and
press ^V and ^O.  cpmemu has the identical open item for the identical reason
and it wants the same machine.

- with --escape=none there is no way into sim> from a running guest at all.
that is the point of it, but it means the debugger is reachable only by
restarting with a different flag.  a two-key sequence - the escape char twice -
would give both, and would let the default stop reserving a WordStar key.
nobody has asked for it.

- the three CDN tags in romwbw.html-template and romwbw-debug.html have no
subresource integrity.  the "a CDN can move" worry in the last sweep was wrong
as stated - xterm@5.3.0 is an exact npm pin, served immutable, and the package
was renamed to @xterm/xterm at 5.4, so that version is frozen - but a jsdelivr
compromise or a TLS intercept still injects arbitrary JS into a page holding
the user's disk images.  add integrity= and crossorigin=, or vendor the three
files into web/ and close the offline gap at the same time (an installed deb
has no terminal without internet: release.yml packages the wasm but not xterm).
regenerate a hash with: curl -sL <url> | openssl dgst -sha384 -binary | openssl
base64 -A

- there is no test of any kind in this repo - no target, no CI step, no script
- so none of the console behaviour just fixed is protected.  the cheap version
is a check: target in src/makefile with two cases: a piped 'a\nb\n' that must
still deliver two CRs, and an openpty case asserting Enter arrives as 0x0D
while Ctrl+J arrives as 0x0A.  both were run by hand for this change and both
would regress silently.

- found while auditing the input path, none of it control-character work, all
of it out of scope for the commit that found it:
  - VDAKRD (hbios_dispatch.cc) does not rewind PC the way CIOIN does when no
  key is pending, so on a build with a text display - the wasm one advertises
  has_text_display = true - the guest returns from it with DE untouched and
  never gets its key.  VDAKST never sets the result byte, so it reports "no
  key" in A whatever is pending.
  - the wasm video/DSKY/sound callbacks are wired to names nothing implements:
  emu_io_wasm.cc emits Module.onVideo*/onDsky*, romwbw.html-template implements
  onVda*/onSnd*.  ~200 lines on both sides that have never executed, and
  Module.onError is dropped entirely, which is why nobody noticed.
  - the whole aux/printer family (printer_set_file, printer_out, printer_ready,
  aux_set_input_file, aux_set_output_file, aux_in, aux_out) has no caller
  anywhere.  LST:, PUN: and RDR: do nothing, and there is no --printer flag to
  reach them.  emu_io_cleanup() also fcloses them and emu_io_init() never
  reopens, so one press of the escape key would kill redirection for the run if
  it were ever wired up.
  - emu_console_write_char drops every CR, not just the CR of a CR LF pair, so
  a guest returning to column 0 without a newline (progress counters, status
  line redraws) overwrites nothing.  OPOST/ONLCR cannot restore a byte that was
  deleted before the tty saw it.  same code in the wasm backend.
  - the web output filter (romwbw.html-template Module.onConsoleOutput) passes
  only 0x08, 0x0A, 0x1B and 0x20-0x7E, so TAB, BEL and FF never reach xterm.
  the CLI putchar()s them.  the ^R sweep in the other direction.
  - romwbw.html-template offers z80cpm_tools.img in both disk selects and no
  such file exists anywhere in the repo.
  - the slice-count selects in romwbw.html-template call
  Module._romwbw_set_disk_slices, which does not exist: romwbw_web.cc defines
  no such entry point and it is not in EXPORTED_FUNCTIONS, so both selects
  silently do nothing.  the count is auto-derived from the number of loaded
  disks anyway, so the honest fix is probably to delete the two selects.
  - release.yml clones avwohl/cpmemu at default-branch HEAD with no tag or SHA
  to build libqkz80.a, and installs emsdk latest.  the second of those already
  broke a release once (13d1c23).
